# Runbook: a credential has leaked

Assume it is in use. Do not begin by working out how it leaked.

1. Issue a replacement credential first. Revoking before replacing turns a
   possible compromise into a certain outage.
2. Deploy the replacement everywhere that uses it. The inventory is in the
   secrets register; if a consumer is not in the register, that is a second
   finding.
3. Revoke the old credential.
4. Search the audit log for uses of the old credential outside our own address
   ranges, from the earliest point it could have leaked.
5. Only now, work out how it leaked. Common answers: a log line, a screenshot in
   a ticket, a repository history, a CI variable printed by a debug build.
6. Write the incident up even if nothing was used. Especially then.

Do not discuss an active credential compromise in a public channel.
