The same agent, the same poisoned document, two paths.

The agent is a parser, not a model — see acp/demo/agent.py. The gateway
never sees an agent's reasoning, only its calls, so a deterministic
stand-in exercises exactly what a model would and does it twice the same.

========================================================================
  ACT TWO — the same agent, through the gateway
========================================================================

  Authenticated as alice. The composed policy allows reads broadly
  and requires a human for mock-a__create_ticket.

  Injection screening is in `report`, and only these detectors
  are permitted to withhold anything:
    - bidirectional_override
    - encoded_payload

  That list is short because it was MEASURED, not reasoned about: those
  two produced zero findings across 106 benign documents (ADR 0039).
  A detector that fires on real documents cannot be allowed to withhold
  them — so a detector can be certain and still not act.

  A learned classifier also scores every result (`report`).
  It catches polite injections the patterns cannot, 64% of BIPIA's
  held-out attacks, but it also flags 2% of clean documents and 23% of
  AgentDojo's clean tool outputs, so it may withhold only when an
  operator sets ACP_FIREWALL_LEARNED=enforce (ADR 0075, 0076, 0080).

========================================================================
  WHAT THE FIREWALL SAW
========================================================================

  #88941  mock-a__read_document  -> allowed
      detectors   None
      families    ['tool_confusion']
      confidence  ['high']
      findings    3
      TRIGGERS    0   <- what could withhold

  `findings` is what the detectors noticed. `triggers` is how many of
  those came from a detector permitted to act. When findings are high
  and triggers are zero, THE FIREWALL SAW IT AND WAS NOT ALLOWED TO
  STOP IT — which is a measurement decision, not a bug.

========================================================================
  WHAT HAPPENED
========================================================================

  Directly:
    - read the runbook: served
    - mock-a__read_document: served
    - mock-a__create_ticket: served

  Through the gateway:
    - read the runbook: served
    - mock-a__read_document: served
    - mock-a__create_ticket: HELD for a human

  Nothing above is asserted in advance. The firewall's measured recall
  on this family is 75% detected, 38% precise (ADR 0047), and this
  payload is deliberately NOT in the corpus — a hand-written attack
  added to the corpus would improve those numbers by construction.

  So read the outcomes above and ask WHICH LAYER STOPPED IT.

  Then look at what was written down:
      make audit-verify
      docker compose exec gateway tail -5 /app/audit/audit.jsonl

  The direct path produced no record at all. That is the other half of
  the argument and it is easy to miss: the first act is not just
  unprotected, it is UNEXPLAINABLE. Nobody could reconstruct it after.

  Entry signing is off in this stack. Without a key, whoever can
  write the chain file can rewrite it consistently; with one, only the
  key holder can (`acp audit keygen`, ADR 0078). The compose stack
  ships no key on purpose: a private key is yours to make, not to clone.
